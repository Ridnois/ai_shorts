# Feedback loop

The vault is the single source of knowledge: feedback is done only when the vault says it.

1. **Record** the user's words verbatim in the video's Status note under *Feedback*.
2. **Find the gap** in one line: what the video did that the user did not want.
3. **Edit the one rule that owns it:** idea, script, picture rules → [[Format]] · look, layout, motion, sound kit, brand → [[Look]] and `hfkit.py` together · stages, tools, checks → [[Production]] · audience, package, upload, policy, numbers → [[Growth]] · agent behaviour → `CLAUDE.md`.
4. **The newest feedback wins:** replace the older rule in the same pass; never keep both. Delete what it replaces (git keeps history).
5. **A fault that comes back twice becomes a check** (`hfkit` warning, `check3d.mjs`, `check_vault.py` invariant), not a reminder.
6. **Apply forward:** renders already waiting ship unless the feedback names a defect in them.
7. **Answer** with what changed where and what is still unverified.

Data (retention, swipes, replays) comes in through [[Growth]] §Analytics; every 10 uploads the targets are replaced by the channel's own medians.
