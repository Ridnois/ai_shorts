# Why 0.1 plus 0.2 is not 0.3

← [[Pipeline]] · [[YouTube Channel]] · [[Audience]]

**Suggested draft, 6 Oct 2026, not researched.** Topic family: software. **Y:** code that adds money correctly. **X:** computers count in binary, so a tenth is an endless fraction that gets cut off.

## Package (promise paid by scene 1)

- **Promise:** Your computer cannot store one tenth, and that quietly breaks code that handles money.
- **Titles:** Your Computer Cannot Store 0.1 (and It Broke a Missile) (recommended) · Why 0.1 + 0.2 Is Not 0.3 in Code · The Tiny Error That Hides in Every Price Calculator
- **Thumbnail:** hero close photo of code or a calculator display (stock, CC); kicker **PROGRAMMING**; lines **0.1 + 0.2** / **IS NOT 0.3** (orange); chips BINARY FRACTION · 1991 PATRIOT · STORE CENTS. ## Draft script (170 words, words per scene in brackets)

1. Your computer cannot store one tenth. That is why code that adds money can quietly be wrong. (17)
2. Computers count in twos, so one tenth becomes an endless binary fraction, like a third in decimal. The machine cuts it off, and every cut leaves a tiny error. First what is lost, then what it cost. (37)
3. Add point one and point two and you get point three, plus a speck. That speck is the part that was cut off. (23)
4. Usually that is harmless. But in nineteen ninety-one, a Patriot missile battery counted time in tenths of a second and ran for days. The cut-off grew into a clock error of about a third of a second. (37)
5. A Scud missile travels over half a kilometer in that time, so the system looked in the wrong place, and the missile got through. Twenty-eight soldiers died. (27)
6. So programmers handle money as whole cents, never as decimals. (10)
7. A whole number of cents is something a machine can hold exactly. A tenth of a dollar is not. (19)
